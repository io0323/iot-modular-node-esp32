# ADR 0005：ポンプの二重の止めを入れない

## 状況

ポンプの連続出力の上限（30秒）は、インターロック `PumpInterlock` として ControlArbiter が control タスクの中でかける。基本設計書 第7章の未決事項に「control タスクとは別に esp_timer でも止めるか」があった（#10）。control タスクが止まったら、ポンプが動き続けるおそれがあるためである。

## 決定

入れない（#10。P8 で決定）。

## 理由

- control タスクを含む4つのタスクは、すべてタスクウォッチドッグに登録してあり、タイムアウトは5秒（#98）。control タスクが止まると5秒でパニックになり、再起動する
- 起動するときは、各アクチュエーターを初期化した直後に 0 を出してから、タスクを起こす（#99）
- そのため、control タスクが止まってもポンプが動き続ける最長は「30秒＋5秒」で、それ以上にはならない
- 二重の止めを入れると、ポンプの出力を決める場所が2つになる。基本設計書 第6章の「出力は ControlArbiter だけが決める」が崩れ、2つの止めの状態をそろえる仕組みが別に要る

## 影響

- ポンプが動き続ける最長は35秒（基本設計書の「連続30秒」より5秒長い）。詳細設計書の「基本設計書との差」に書いた
- タスクウォッチドッグからの再起動と、次の BOOT が watchdog になることは、Wokwi のシナリオ `wokwi/scenarios/watchdog.yaml` で確かめた。QEMU ではタスクウォッチドッグが働かない（#131）
- 実機で、リレーの応答と再起動の時間を含めて確かめるのは、実機フェーズ
